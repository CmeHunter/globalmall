需求變更說明：折抵方案判斷專櫃抽成類別

文件日期：2026-11-20 狀態：待確認，確認後再評估工時與報價

需求：EC 在查詢會員時傳入專櫃抽成代碼，讓系統依抽成代碼選出對應的點數折抵方案。

做法：後台「折抵方案設定」新增兩個欄位；EC 使用的兩支 API 各新增一個選填欄位；POS 點數扣抵也套用新設定。

影響：新欄位都是選填。沒有設定、沒有傳入時，照現行規則判斷，現有的折抵方案與 EC、POS、APP 串接都不受影響。

一、已確認事項

項目決定
EC 查詢會員時傳入幾個抽成代碼一個
EC 點數折抵時是否再傳一次要，再傳一次相同的抽成代碼
套用範圍EC 與 POS 都套用；現有方案與現有串接方式維持原樣
抽成比例範圍開放在後台設定（目前固定 7%～100%）
POS 交易有商品不符合方案限定的抽成類別時跟現在一樣，整筆不能折抵
折抵方案列表不顯示新欄位
沒有設定「限定抽成類別」的方案一律用現金抽成代碼 0 判斷，跟現在完全一樣，不受 EC 傳入的代碼影響

二、調整內容

1. 後台「折抵方案設定」新增兩個欄位

欄位用途設定方式不設定時
限定抽成類別 這個方案只給哪些抽成類別使用 多選，選項為專櫃抽成資料裡的代碼與名稱 空白＝不限定，照現行規則判斷
抽成比例範圍 專櫃在該抽成類別下的抽成比例，要落在範圍內才能使用這個方案 填起、迄兩個數字（%），含頭尾 預設 7～100，跟現在一樣

方案審核時也看得到這兩個欄位（唯讀）。

2. EC 使用的 API 各新增一個選填欄位

API新增欄位說明
M01001 會員查詢 commission_code（專櫃抽成代碼，選填） 系統依這個代碼挑選可用的折抵方案
T05005 EC 點數折抵 commission_code（專櫃抽成代碼，選填） 請傳與 M01001 相同的代碼，系統會用同樣的規則再檢查一次

訂單成立（T05001）、交易確認（T05002）與取消類 API 不變。

3. POS 點數扣抵套用新設定

POS 電文不變。方案設定了「限定抽成類別」時，交易裡每個商品的抽成類別都必須在清單內、比例也在範圍內；只要有一個不符合，整筆就不能折抵（與現在比例不符時的處理相同）。

三、系統判斷方式

系統依方案的「優先順序」由大到小逐一檢查，用第一個全部符合的方案：

  1. 方案沒有設定限定抽成類別：一律用現金抽成代碼 0 的比例比對抽成比例範圍（跟現在一樣）。
  2. 方案有設定限定抽成類別：
    • EC 傳入的抽成代碼必須在清單內（沒傳時視為 0）。
    • 該專櫃在這個抽成代碼下的比例，必須在方案的抽成比例範圍內。
  3. 專櫃查不到該抽成代碼的抽成資料時，這個方案不符合。

以下抽成代碼 A、B 與各比例為假設值，僅供說明。

五、設定注意事項

  • 限定抽成類別的方案，優先順序要設得比通用方案高。否則系統會先檢查到通用方案並直接採用，限定方案就用不到。
  • 抽成比例範圍含頭尾。例如設定 7～100 時，抽成剛好 7% 的專櫃也符合。

六、不受影響的部分

  • 現有的折抵方案：上線後「限定抽成類別」為空白、抽成比例範圍保留原值，判斷結果不變。
  • EC、POS、APP 現有的串接：不傳新欄位就照現行規則判斷，不需要配合修改。
  • 後台新增方案時不填新欄位：結果與現在新增的方案相同。

七、需要 EC 廠商配合

  • M01001 會員查詢每次呼叫都帶 commission_code。EC 一次結帳會呼叫 M01001 多次，每次都要帶相同的值，結果才會一致。
  • T05005 點數折抵帶與 M01001 相同的 commission_code。
  • API 規格書更新後會提供給廠商。
